# 程式碼用途分析

更新日期：2026-07-27

## 一句話定位

本專案是一套給個人或小型影視製作團隊使用的 Web 營運控制台：以客戶和影視案件為主軸，在同一處管理製作流程、任務狀態、預算、應收款與應付款。

## 主要使用情境

1. 使用者以 Email 和密碼註冊、登入。
2. 建立客戶，並將影視專案歸屬到客戶名下。
3. 依案件類型選擇工作模板：
   - 一般製片
   - 短影音剪輯
   - 長影音剪輯
   - 節目企劃
   - 導演
4. 在看板上建立、編輯、拖曳及刪除製作任務。
5. 讓製作任務自動連動收入或支出項目。
6. 追蹤預算、待收、已收、待付、已付，並匯出財務 CSV。
7. 將資料先保存在瀏覽器，並同步到登入者自己的 Supabase 帳戶資料。

## 功能分區

### 登入與資料隔離

- Supabase Auth 負責註冊、登入、登出及 Session。
- API 操作前會取得目前使用者；未登入者不能讀寫專案或客戶。
- `clients` 和 `film_projects` 都以 `owner_id` 歸屬使用者。
- Supabase Row Level Security 再次限制使用者只能管理自己的資料。

### 客戶與專案大廳

- 專案依客戶分組，未指定客戶的專案放在「未分類客戶」。
- 可新增客戶、建立專案、重新指定專案客戶。
- 專案卡片顯示最近更新時間、任務數及待支付金額。
- 刪除專案前要求確認，並提供 6 秒復原時間。

目前客戶資料模型也預留聯絡 Email、電話與備註；介面目前主要提供客戶名稱及聯絡人輸入。

### 製作任務看板

- 當前介面將非財務工作集中到 `Scripting` 所代表的「專案主流程」。
- 每種專案模板提供不同狀態，例如短影音的「待收素材 → 剪輯中 → 待確認 → 修改中 → 已交付」。
- 任務支援標題、說明、負責人、期限、金額、交易資訊與狀態等欄位。
- 任務可用拖放方式換狀態。
- 切換模板時保留既有任務；不相容的狀態會移到新模板的第一個狀態。

雖然型別仍保留 `OnSite`、`PostProduction` 模組，現行工作區只直接顯示主流程與財務兩個入口；舊模組資料在清理或切換模板時會合併到主流程。

### 製作與財務連動

- 一般製作任務會自動建立一筆連動支出。
- 短影音任務可輸入單支收入，並自動建立連動收入。
- 節目企劃任務可同時建立連動成本與收入。
- 製作任務完成後，連動收入會標記為可收款。
- 變更製作任務名稱時，連動財務項目的名稱會一併更新。
- 刪除任務時，相關連動財務項目也會一併刪除。
- 財務狀態移到最後一欄時，會同步標記為已付款／已收款並記錄時間；取消完成狀態時可回復原狀態。

### 財務管理

- 將所有收入與支出都存成 `Finance` 任務，而不是另一套獨立交易資料表。
- 儀表顯示尚未收款、尚未支付、本期已收與本期已付。
- 一般案件可設定單一專案總預算，並比較實際支出、待支付與剩餘預算。
- 收支明細可依類型、完成狀態及月份篩選。
- 可手動新增收入或支出，並匯出 UTF-8 CSV。
- 短影音案件會依收入交易月份，自動彙總支數、總額、待收與已收。

## 資料與同步方式

```text
React 介面
  ↕
useProjectData（本機狀態、600 ms 延遲儲存）
  ├─ localStorage：離線快取
  └─ /api：雲端同步
       ↕
服務層：驗證、資料清理、業務摘要
       ↕
Repository
       ↕
Supabase：Auth + PostgreSQL + RLS
```

- 開啟專案時先顯示本機快取，再嘗試讀取雲端；若雲端成功回應，雲端版本優先。
- 每次專案資料改變後，會延遲 600 ms 寫入 `localStorage` 並上傳雲端。
- 雲端失敗時本機資料仍可操作，介面顯示同步失敗並提供重試。
- 專案的主要內容整包存入 `film_projects.project_data` JSONB；客戶關係則使用 `client_id` 關聯欄位。
- 讀取舊資料時會清理無效任務、補預設值、合併舊模組，並把舊版短影音月結資料轉成收入任務。

## 程式架構責任

| 路徑 | 用途 |
| --- | --- |
| `app/page.tsx` | 登入畫面、專案工作區及主要頁面切換 |
| `app/client-dashboard.tsx` | 客戶優先的專案大廳 |
| `app/project-finance-panel.tsx` | 財務摘要、預算、篩選、明細與 CSV |
| `hooks/useProjectData.ts` | 專案狀態、本機快取、雲端同步及操作介面 |
| `lib/project-data.ts` | 專案模板、建立、資料清理與舊資料遷移 |
| `lib/projects/task-logic.ts` | 任務和財務項目的連動規則 |
| `app/api/**` | Auth、客戶及專案 HTTP API |
| `lib/services/project-service.ts` | 身分驗證、輸入驗證及應用服務 |
| `lib/repositories/project-repository.ts` | Supabase 資料存取 |
| `supabase/schema.sql` | 資料表、索引、外鍵及 RLS |
| `types/project.ts` | 專案、任務、客戶、財務及模板型別 |
| `tests/**` | 資料清理、模板切換、任務連動及 API 回應測試 |

## 目前邊界與值得注意的狀況

- 這是單一使用者擁有資料的模型，尚未看到團隊成員、角色或專案共享權限。
- 離線策略是快取與失敗重試，不是完整的雙向同步；雲端載入成功時會覆蓋本機版本，尚無版本號、衝突合併或多裝置並行編輯機制。
- 專案內容採單一 JSONB 文件儲存，開發簡單，但日後若需要跨專案查詢任務、交易報表或大量資料分析，會受到限制。
- 財務資料是營運追蹤用途，未包含成本分類、會計科目、稅額、幣別、發票檔案上傳、審批或正式帳務流程。
- `MonthlySettlement` 型別與 Hook 操作仍存在，但目前資料清理會把舊月結轉為收入任務，財務畫面也改以收入任務自動彙總；這部分屬於舊版相容層。
- `lib/api/project-api.ts` 與 `lib/client/project-api.ts` 有重複實作；目前介面使用後者，前者缺少客戶 API 且未處理 HTTP 204，較像尚未移除的舊檔。
- 自動化測試目前集中在核心資料和任務規則，尚未涵蓋完整登入流程、客戶操作、同步衝突、財務 UI 與端對端流程。

## 結論

程式目前的產品核心不是「收藏或管理影片」，而是「管理影視接案的執行與現金流」。它把客戶、案件流程及簡化財務連結在一起，適合個人工作者或小型製作團隊追蹤每個案子的工作進度、預算與收付款狀態。
